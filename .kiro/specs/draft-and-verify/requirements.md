# 需求：決定書草稿撰寫與檢查模組

## 背景

新北市訴願案量自 110 年 1,238 件增至 114 年 1,566 件，以洗錢防制法、廢棄物清理法、
空氣污染防制法三類為最大宗。這類案件法規適用與爭點高度重複，但每份決定書仍須承辦人
逐一撰擬校對，且人工檢索函釋易有遺漏，導致法理涵攝不周而事後被法院撤銷。

本模組承接前段「已受理 + 已分類」的輸出，負責**按案由撰寫草稿並自動檢查**。

## 範圍

```
同學（前段）                      本模組
──────────────────────  ▶  ────────────────────────────
PDF → 受理判斷 → 案由分類     路由 → 撰稿 → 檢查 → 審查
              （JSON 介面交接）
```

## 功能需求

### R1 案由路由

- R1.1 讀交接 JSON 的 `route_key`，分派到對應案由設定。
- R1.2 `route_key` 為英文枚舉（六個），未知值安全退回 `general`，不得擋流程。
- R1.3 `need_human_review` 為真時仍須正常路由，只在輸出標記。

### R2 法規與案例檢索（RAG）

- R2.1 透過 Bedrock Knowledge Bases 檢索，不自建索引。
- R2.2 法規/函釋/判解可依案由過濾，並帶入共通法規（訴願法、行政程序法等）。
- R2.3 歷史決定書不硬過濾案由（樣本少），案由作為加權特徵。
- R2.4 檢索結果須附來源，供引用追溯。

### R3 主文自動判定

- R3.1 前段判不受理者走快速通道：套訴願法§77 款次模板，不呼叫 LLM。
- R3.2 原處分健檢有紅燈者，判「原處分撤銷，另為適法之處分」。
- R3.3 否則依相似案例主文多數決；無資料時預設「訴願駁回」。
- R3.4 須輸出判定依據（`decision_basis`），可解釋。

### R4 草稿生成

- R4.1 依案由切換 prompt 與檢索範圍，達成「案由專責」效果。
- R4.2 逐一回應每項訴願主張並標注編號（`responds_to`）。
- R4.3 **不得引用檢索清單以外的法條、函釋或判決字號**。
- R4.4 不得新增案件事實中沒有的內容。
- R4.5 不得變更主文結論方向。

### R5 草稿自動檢查（純規則）

須以程式判定下列項目，**不呼叫 LLM**：

| 檢核項 | 對應風險 |
|---|---|
| 引用條文在可引用清單內 | 字號捏造 |
| 內文條號均已宣告於 `cites` | 追溯性不完整 |
| 條號書寫正確（含「之2」） | 條號誤植 |
| 每項訴願主張皆有回應 | 理由不備 |
| 引用條文於行為時有效 | 適用法規錯誤 |
| 理由日期見於案件事實 | 日期幻覺 |
| 訴願期間計算一致 | 程序判斷錯誤 |
| 教示完備且法院名稱有效 | 引用已裁撤法院 |
| 主文與理由結論一致 | 主文理由矛盾 |
| 健檢紅燈已於理由處理 | 未審酌之瑕疵 |

- R5.1 結果分三級：red（必須處理）/ amber（提醒複核）/ green（通過）。
- R5.2 資料不足時回 **skipped 而非 fail**，避免骨架階段產生假紅燈。
- R5.3 須輸出可塞回重寫 prompt 的問題清單（`issues`），只收紅燈。

### R6 對抗式審查

- R6.1 以高階模型扮行政法院法官，找「可能據以撤銷訴願決定的瑕疵」。
- R6.2 只挑影響裁判結果的重大問題，不挑文字風格。
- R6.3 輸出 `passed` / `attacks`（含 severity 與修正方向）/ `revocation_risk`。

### R7 有限重寫

- R7.1 規則紅燈或法官指出重大問題時，帶審查意見重寫。
- R7.2 重寫上限 1 次，僅修正被指出的段落，不整篇重寫。
- R7.3 重寫後仍不通過時標 `needs_human_review`，**但仍輸出**，不阻斷流程。

## 非功能需求

### N1 競賽規範

- N1.1 Bedrock 請求 ≤ 1 RPS，含跨行程情況。
- N1.2 單件呼叫數可預測：正常 3 次，最壞 5 次，不受理案 0 次。
- N1.3 不使用 Bedrock Agents（呼叫數不可預測）。
- N1.4 上傳 KB 前須去識別化。

### N2 可追溯

- N2.1 每個引用可對回檢索來源。
- N2.2 檢核報告須指出具體證據（哪一條引用、哪個主張編號）。

### N3 可離線開發

- N3.1 未接 KB / 無憑證時可用 dry-run 跑完整流程。
- N3.2 純規則部分（路由、檢查）不需 AWS 即可測試。

## 驗收標準

- A1 乾淨草稿 → 檢核全綠或 skipped，無紅燈。
- A2 含捏造引用、漏回應、主文矛盾的草稿 → 對應項目報紅燈並列出證據。
- A3 骨架空資料 → 全部 skipped，不誤報。
- A4 紅燈草稿 → 觸發重寫一次，修正後紅燈清空。
- A5 不受理案 → 0 次 Bedrock 呼叫。
- A6 兩個行程同時呼叫 → 所有間隔 ≥ 1 秒。
