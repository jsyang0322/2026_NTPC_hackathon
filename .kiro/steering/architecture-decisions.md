# 架構定案（已鎖定，變更前先討論）

這些決策已經評估過取捨，不要在實作時默默改掉。

## 一套核心，多種外殼

業務邏輯全部寫在 `core/` 的純函式：**dict 進、dict 出，不綁執行環境**。

四種外殼共用同一份 `core/`：

| 外殼 | 定位 |
|---|---|
| 單體應用（Streamlit） | Demo 主線 |
| AWS Lambda | 可雲端化 |
| Step Functions | 簡報「正式架構」 |
| S3 事件觸發 | 全自動展示 |

外殼只負責「取輸入 → 呼叫 core → 寫輸出」，**不重寫任何業務邏輯**。

## 不使用 Bedrock Agents

這是**團隊技術選擇，不是競賽規範限制**（規範只要求 ≤ 1 RPS）。簡報時不要講成「規範不准」。

理由：

1. `InvokeAgent` 會代使用者發出多次 `InvokeModel`（官方文件證實），且這些呼叫
   計入同一份配額。在 ≤ 1 RPS 下呼叫數不可預測，容易卡住 Demo。
   AgentCore 的「迭代上限」只能限制**次數天花板**，管不到**每秒速率**。
2. 本系統是固定管線（路由 → 檢索 → 撰稿 → 驗證 → 審查），不需要 Agent 的自主性。
   Agents 的價值是「讓 AI 自主決定步驟」，與本專案「可控、可追溯」的目標相反。
3. 引用可追溯性難掌控——我們要求「只能引用檢索清單內的法條」，Agent 自行決定
   檢索什麼時較難硬性保證。

替代作法：`draft.CASE_PROFILES`——**同一顆 Claude + 依 `route_key` 切換
prompt 與 KB 檢索範圍**，達成「案由專責」效果。文件裡說「洗錢 agent」時，
指的是這組設定，不是 AWS 託管 Agent。

正名：本系統是**固定編排的工作流（workflow）**，不是自主 agent。

## RAG 走路線 A：Bedrock Knowledge Bases 託管

向量化、索引、檢索全交 AWS；自己只寫「呼叫 Retrieve API + metadata 過濾」。

知識庫組織：**單一 KB + metadata 過濾**（非每案由一個 KB），
每份文件附 `case_type` / `doc_type` / `year`。

過濾策略有分別，不要寫成一樣：

- **法規/函釋/判解**：可依案由硬過濾，並帶入共通法規（`doc_type=common_law`）
- **歷史決定書**：**不硬過濾案由**（實體案樣本少），案由當加權特徵

已知限制：S3 Vectors 主要支援語意檢索，中文條號精確比對（「第15條之2」勿抓成
「15」）靠純語意可能不準。**補償方式**：在 `verify_draft()` 用正則事後校驗
（V2/V3），把「檢索不夠精確」的風險移到「生成後檢查」補回來。

## 品質把關：規則與 LLM 分工

刻意分兩層，不要混在一起：

| 層 | 模組 | 抓什麼 | 成本 |
|---|---|---|---|
| 規則層 | `core/verify.py` | 可程式判定的客觀錯誤：引用捏造、漏回應、日期矛盾、條號寫壞 | 0 次呼叫 |
| 法官層 | `core/critic.py` | 需要法律判斷的弱點：涵攝跳躍、回應薄弱、漏審瑕疵 | 1 次呼叫 |

原則：**能用規則就不用模型**。用會幻覺的東西檢查幻覺是循環論證，
規則層必須比被檢查對象更可靠，所以只能純 Python。

`verify.py` 的輸出分兩路：

- `blocking` / `summary` → 給人看（介面、事後抽查）
- `issues` → 給機器用（塞回重寫 prompt）

只有**紅燈**進 `issues` 觸發重寫；黃燈僅提示，避免為語意模糊的項目多花一次呼叫。

## 流程 v1.3：全自動，無人工閘門

```
前段 JSON → Router → KB 檢索 + 自動判定主文
          → 撰稿 → 規則檢查 → 法官審查 →（有問題）重寫 ≤1 次
          → 輸出草稿 + 檢核報告
```

主文判定順序（`pipeline._decide_disposition`）：

1. 前段判不受理 → 訴願不受理（快速通道，**0 次 Bedrock 呼叫**）
2. 健檢有紅燈 → 原處分撤銷，另為適法之處分
3. 否則依相似案例主文多數決；無資料時預設訴願駁回

仍不通過時標 `needs_human_review`，**但不阻斷輸出**（供事後抽查）。

單件呼叫預算：檢索 1 + 撰稿 1 + 法官 1 = **3 次**；觸發重寫最壞 **5 次**；不受理案 **0 次**。
